# راهنمای امن امضای نسخهٔ انتشار

## چرا کلید جدید لازم است؟

کلید امضای قبلی در تاریخچهٔ مخزن عمومی افشا شده است و نباید برای نسخه‌های بعدی استفاده شود. حذف فایل از شاخهٔ جاری، نسخه‌های قبلی تاریخچه را پاک نمی‌کند. کلید جدید باید محرمانه و تحت کنترل مالک برنامه نگهداری شود.

## بستهٔ کلید انتشار جدید

یک keystore تازه با alias برابر `padnakasht-release` و رمزهای تصادفی قوی برای این پروژه ساخته و از نظر alias/گواهی بررسی شده است. بستهٔ خصوصی تحویلی شامل فایل JKS و فایل `GITHUB-ACTIONS-SECRETS.txt` است. فایل متنی، مقدار Base64 و سه مقدار دیگر را دارد؛ آن را فقط برای ثبت Secretها در مخزن خصوصی استفاده کنید و در Git commit نکنید. اثرانگشت عمومی گواهی SHA-256:

`e646d3a76c9b2932fdf61fb76ee32de6f8bb7983e9fc93fe806e7f78b4b7ba64`

Workflow هنگام بررسی APK نهایی همین اثرانگشت را کنترل می‌کند؛ کلید دیگری پذیرفته نخواهد شد.

## ساخت کلید جایگزین روی رایانهٔ شخصی

به JDK 17 یا جدیدتر نیاز است. در PowerShell ویندوز:

```powershell
keytool -genkeypair -v -keystore .\padnakasht-release.jks -alias padnakasht-release -keyalg RSA -keysize 3072 -sigalg SHA256withRSA -validity 10000
```

برای گذرواژهٔ مخزن و کلید، دو گذرواژهٔ قوی و متفاوت انتخاب کنید. فایل `padnakasht-release.jks` را در فضای امن و آفلاین نگه دارید. اگر این فایل یا گذرواژه‌ها گم شوند، انتشار به‌روزرسانی‌های سازگار با همین امضا ممکن نخواهد بود.

برای ساخت مقدار Base64 در PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path .\padnakasht-release.jks))) | Set-Clipboard
```

## ثبت Secretها در GitHub

در مخزن GitHub به مسیر زیر بروید:

`Settings → Secrets and variables → Actions → New repository secret`

چهار Secret با نام دقیق زیر بسازید. مقادیر دقیق برای کلید تحویلی در فایل `GITHUB-ACTIONS-SECRETS.txt` داخل بسته آمده است:

- `RELEASE_KEYSTORE_BASE64`: مقدار Base64 فایل JKS
- `RELEASE_STORE_PASSWORD`: گذرواژهٔ مخزن JKS
- `RELEASE_KEY_ALIAS`: مقدار `padnakasht-release`
- `RELEASE_KEY_PASSWORD`: گذرواژهٔ کلید

مقادیر را در پیام یا کد مخزن قرار ندهید. هرگز فایل JKS را commit یا در Artifact عمومی آپلود نکنید.

## انتشار

پس از ثبت هر چهار Secret، تغییرات شاخهٔ تأییدشده باید به `main` برسند. اجرای CI روی `main` ابتدا آزمون‌ها را اجرا می‌کند، سپس APK Release را می‌سازد، امضای APK و شناسهٔ بسته/نسخه را بررسی می‌کند و فقط در صورت موفقیت، GitHub Release آزمایشی منتشر می‌کند.

## هشدار سازگاری

کلید جدید با کلید افشاشدهٔ قدیمی یکسان نیست. نصب نسخه‌ای که با کلید قدیمی امضا شده ممکن است به‌روزرسانی درجا را نپذیرد. پیش از حذف نسخهٔ نصب‌شده، داده‌ها را از داخل برنامه پشتیبان بگیرید. پشتیبان فعلی به کلید Keystore همان نصب وابسته است و انتقال بین دستگاه‌ها را پوشش نمی‌دهد.
