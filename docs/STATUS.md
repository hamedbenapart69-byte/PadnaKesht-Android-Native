# وضعیت واقعی پروژهٔ پادناکِشت

## قابلیت‌های پیاده‌سازی‌شده در شاخهٔ فعلی

- اپلیکیشن بومی Kotlin + Jetpack Compose + Material 3 با رابط فارسی RTL، تاریخ شمسی، تومان و تم روشن/تیره
- مشتری‌ها، اصلاح مانده حساب، کالاها، SKU، دسته‌بندی و موجودی
- مقدارهای کسری و واحدهای مقیاس‌دار
- فاکتور چندقلمی، تخفیف، دریافت جزئی/کامل، لغو فاکتور و برگشت کالا
- بازپرداخت جزئی/کامل وجه با کلید idempotency، کنترل سقف بازپرداخت و حفظ سابقهٔ رسید
- دفتر خرید تأمین‌کنندگان، ورود موجودی، پرداخت جزئی و ماندهٔ پرداختنی
- دفتر مالی عمومی، گزارش فروش فاکتوری، دریافتی، بازپرداخت، ماندهٔ مشتریان و بدهی تأمین‌کنندگان
- خروجی PDF و XLSX
- Room با Migrationهای ثبت‌شده تا نسخهٔ ۱۳
- SQLCipher، کلید محافظت‌شده با Android Keystore، PIN مبتنی بر PBKDF2، قفل مجدد در پس‌زمینه و biometric در دستگاه پشتیبانی‌شده
- پشتیبان‌گیری/بازیابی رمزنگاری‌شده برای همان نصب
- نمودارها و تحلیل آفلاین؛ پیش‌بینی فعلی میانگین متحرک است، نه ML آموزش‌دیده

## معماری واقعی

کد در ماژول فعلی `app` و پکیج‌های مجزا قرار دارد:
- `data/local`: Room، Entityها، DAOها و Migrationها
- `data`: Repository و جریان داده
- `domain`: قوانین حسابداری و محاسبات مستقل
- `security`: کلید دیتابیس، PIN و قفل برنامه
- `report`: خروجی PDF و XLSX
- `ui`: صفحه‌ها و اجزای Compose

پروژه هنوز چندماژولی نشده است؛ در این مرحله، جداسازی لایه‌ها درون ماژول app انجام شده تا بازنویسی غیرضروری ایجاد نشود.

## تصمیم داده‌های اولیه

واردکنندهٔ Excel در نسخهٔ فعلی فعال نیست. ثبت و اصلاح مشتری‌ها، کالاها و مانده‌های اولیه از داخل اپ انجام می‌شود. دادهٔ ساختگی یا نمونه‌ای به‌عنوان دادهٔ واقعی وارد نشده است.

## محدودیت‌های باقی‌مانده

- تست روی گوشی فیزیکی Xiaomi Redmi Note 13
- پشتیبان قابل‌انتقال پس از حذف برنامه/نصب مجدد یا انتقال به گوشی دیگر
- واردکنندهٔ Excel
- اعلان سیستمی برای بدهی‌های بیش از ۳۰ روز
- انتشار APK امضاشدهٔ Release

## رخداد امنیتی امضای قبلی

- کلید و اعتبارنامهٔ امضای قبلی در تاریخچهٔ مخزن عمومی افشا شده‌اند؛ استفادهٔ مجدد از آن ممنوع است.
- فایل‌های کلید از شاخهٔ جاری حذف و مسیرهای مربوطه در `.gitignore` قرار گرفته‌اند؛ این کار تاریخچهٔ عمومی Git را پاک نمی‌کند.
- انتشار Release فقط با کلید جدید و GitHub Actions Secrets انجام می‌شود.
- Secrets لازم:
  - `RELEASE_KEYSTORE_BASE64`
  - `RELEASE_STORE_PASSWORD`
  - `RELEASE_KEY_ALIAS`
  - `RELEASE_KEY_PASSWORD`
- در نبود این Secrets، CI آزمون و Debug APK را می‌سازد اما Release امضاشده را منتشر نمی‌کند.
- کلید جدید ممکن است با نصب‌های امضاشده با کلید قبلی سازگار با به‌روزرسانی نباشد؛ این موضوع باید پیش از انتشار عمومی تعیین تکلیف شود.

## وضعیت نهایی فعلی

کد و آزمون‌های CI در شاخهٔ توسعه تأیید شده‌اند؛ انتشار امضاشده هنوز به چرخش امن کلید و ثبت Secrets نیاز دارد. پشتیبان فعلی نیز به همان نصب وابسته است.
