# وضعیت پیاده‌سازی

## موجود در کد فعلی
- پروژهٔ مستقل Kotlin + Jetpack Compose + Material 3؛ تم روشن/تاریک مطابق تنظیم سیستم
- Room با Flow، Repository، مدل‌های مالی با واحد صحیح پول و Migration نسخهٔ ۱ به ۲
- رمزنگاری دیتابیس با SQLCipher؛ کلید تصادفی دیتابیس با AES-GCM و کلید پوشانندهٔ غیرقابل‌استخراج در Android Keystore نگهداری می‌شود
- راه‌اندازی PIN محلی با PBKDF2-HMAC-SHA256، salt تصادفی، مقایسهٔ امن و تأخیر افزایشی پس از تلاش‌های ناموفق
- ورود زیستی از طریق Android BiometricPrompt در دستگاه‌های پشتیبانی‌شده
- ثبت/حذف تراکنش‌ها، محاسبهٔ جمع درآمد/هزینه/خالص، دسته‌بندی واژه‌محور آفلاین
- نمودارهای Compose برای ترکیب درآمد/هزینه، تراکنش‌های اخیر و روند خالص
- نوشتن گزارش PDF و فایل واقعی XLSX از طریق انتخاب‌گر ذخیره‌سازی اندروید
- مدل پایهٔ پیش‌بینی میانگین متحرک سه دورهٔ اخیر؛ این مدل ML آموزش‌دیده نیست
- مدل‌های Room برای مشتری، کالا/موجودی، فاکتور، ردیف فاکتور و پرداخت
- ثبت فاکتور در تراکنش اتمیک دیتابیس، جلوگیری از موجودی منفی، کنترل مبلغ ردیف و جلوگیری از دریافت بیش از مانده؛ لغو فاکتور موجودی را برمی‌گرداند
- تست‌های JUnit و تست‌های instrumentation برای رمزنگاری فایل دیتابیس، UI اولیه و ناورداهای فاکتور/موجودی/پرداخت

## محدودیت‌ها و کارهای باقی‌مانده
- آخرین اجرای تأییدشدهٔ پیش از اصلاح امنیتی: run #89؛ این نتیجه فقط وضعیت همان Commit قدیمی را ثابت می‌کند. اصلاحات امنیتی جدید باید در CI دوباره ساخته و آزمایش شوند
- صفحه‌های کامل مدیریت مشتری و کالا، ساخت/ویرایش فاکتور و ثبت پرداخت هنوز به UI متصل نشده‌اند؛ فعلاً فقط مدل/DAOهای دامنهٔ تجاری آماده‌اند
- تست‌های Migration از دیتابیس واقعی نسخهٔ قدیمی و آزمون بازیابی/پشتیبان‌گیری هنوز لازم‌اند
- بررسی امنیتی مستقل، تست روی دستگاه فیزیکی، بررسی حالت airplane mode و ارزیابی دسترس‌پذیری هنوز انجام نشده‌اند
- نمودارها و خروجی‌ها باید پس از اجرای موفق build روی دستگاه از نظر نمایش فارسی و سازگاری فایل با برنامه‌های مقصد تأیید شوند

تا زمانی که CI و معیارهای پذیرش واقعی پاس نشده‌اند، این مخزن را نسخهٔ توسعه‌ای بدانید، نه نسخهٔ نهایی انتشار.


## رخداد امنیتی امضای انتشار — وضعیت فعلی

- اعتبارنامه‌ها و keystore امضای قبلی در مخزن عمومی قرار گرفته بودند؛ بنابراین باید افشاشده و غیرقابل‌اعتماد فرض شوند.
- فایل‌های `app/signing.properties` و `app/padnakesht-release.jks` از شاخهٔ فعلی حذف شده‌اند و الگوهای مربوط به فایل‌های امضا به `.gitignore` افزوده شده‌اند.
- پیکربندی Gradle دیگر اسرار امضا را از فایل داخل مخزن نمی‌خواند. امضای انتشار فقط با متغیرهای محیطی حاصل از GitHub Actions Secrets انجام می‌شود.
- گردش‌کار CI در صورت نبود اسرار جدید، تست‌ها و ساخت Debug را ادامه می‌دهد ولی انتشار APK امضاشده را رد می‌کند. اسرار لازم: `RELEASE_KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`.
- **این اصلاح فایل‌ها را از آخرین نسخه حذف می‌کند، اما به‌تنهایی تاریخچهٔ عمومی Git را پاک نمی‌کند و کلید افشاشده را باطل نمی‌سازد.** چرخش کلید و پاک‌سازی تاریخچه هنوز تأیید نشده‌اند.
- کلید جدید باید خارج از مخزن تولید و در مخزن GitHub به‌عنوان Actions Secrets ثبت شود. دسترسی فعلی این اجرا امکان ثبت مستقیم مقادیر محرمانهٔ Secrets را فراهم نمی‌کند؛ از تولید یا افشای دوبارهٔ کلید قبلی خودداری شود.
- استفاده از کلید جدید ممکن است نصب‌های امضاشده با کلید قبلی را از به‌روزرسانی عادی محروم کند. امکان انتقال امن امضا باید بر اساس قابلیت‌های واقعی Android و وضعیت کلید قبلی بررسی شود؛ در غیر این صورت، مهاجرت کاربران نیازمند مسیر نصب مجدد/انتقال دادهٔ امن خواهد بود.

## وضعیت انتشار

- تا زمانی که کلید جدید خارج از مخزن تولید و Secrets لازم ثبت نشده باشند، انتشار امضاشده عمداً مسدود است.
- APK قدیمی منتشرشده محصول نهاییِ تأییدشده محسوب نمی‌شود؛ اصلاح امنیتی حاضر نیز بدون اجرای موفق CI روی Commit جدید، هنوز از نظر Build و تست تأیید نشده است.
